# Constraint Lab

A small **C++17 + Python** project that solves logic puzzles with generalized backtracking and AC-3 constraint propagation, then visualizes the search in an offline browser replay.

**Included puzzles:** N-Queens with fixed/blocked cells, and decimal cryptarithmetic such as `SEND+MORE=MONEY`. No third-party C++ or Python packages are required. The replay uses a small HTML/CSS/JavaScript interface generated by Python.

## Try the included demos

Open `examples/nqueens.html` or `examples/cryptarithm.html` in a browser. These files already contain a solved puzzle and its recorded search; they need no build, server, or internet connection.

Use **Play**, **Pause**, **Reset**, the arrow buttons, speed selection, and the timeline to inspect decisions, domain pruning, failed branches, and backtracking. The dropdown switches between the recorded search and saved solutions. The domain panel and constraint graph update together. Arrow keys and Space also control replay when a form control is not focused.

## Build and run

Requirements: a C++17 compiler, CMake 3.16+, Python 3.9+, and a modern browser. Run these commands from the project directory:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure

python3 python/visualize.py nqueens 8 --open
python3 python/visualize.py cryptarithm 'SEND+MORE=MONEY' --limit 0 --open
```

On Windows, use `python` if that is your Python command. The visualizer detects `build/Release/solver.exe`; pass `--solver PATH` for a custom build location. For CLI examples below, replace `build/solver` with your executable path if needed.

```sh
# Enumerate every 8-Queens solution; output is machine-readable JSON.
build/solver nqueens 8 --limit 0 --timeout-ms 0 --trace-limit 0

# Fix the queen in column 0 at row 1 and forbid column 2, row 3.
python3 python/visualize.py nqueens 8 --fix 0:1 --block 2:3 --open

# Persist the raw trace and render it again later.
python3 python/visualize.py nqueens 8 --save-json build/run.json --output build/run.html
python3 python/visualize.py replay build/run.json --output build/replayed.html

# A deterministic work budget, useful when comparing algorithms.
build/solver nqueens 12 --limit 0 --max-nodes 1000 --timeout-ms 0

# Compare against backtracking without propagation.
python3 python/benchmark.py

# Reproduce a different random test suite.
python3 tests/run_tests.py --seed 42 --cases 100 --report build/seed-42.json
```

## How it works

1. A model defines variables, finite domains, and binary relations. Each relation creates two directed arcs in an adjacency-list graph.
2. AC-3 removes a value from a variable when the neighboring domain contains no compatible value. A changed domain schedules its incoming arcs again. An empty domain rejects the branch.
3. Backtracking chooses the variable with the **minimum remaining values (MRV)**, breaking ties by the number of unassigned neighboring constraints. Values are tried in ascending order for deterministic results.
4. A trail records only domains that changed. Returning from a branch restores those domains to the checkpoint.
5. The solver validates singleton assignments and emits JSON containing solutions, counters, graph metadata, and a bounded sequence of replay snapshots. Python embeds this data into a standalone HTML file.

### Puzzle encodings

**N-Queens:** variable `Qc` stores the row of the queen in column `c`. Every column pair enforces different rows and different diagonals. Fixed and blocked cells restrict initial domains. All coordinates are zero-based `column:row`.

**Cryptarithmetic:** each letter is a digit variable. Pairwise inequality relations enforce distinct digits, and multi-letter words cannot start with zero. Each column obeys:

```text
left_digit + right_digit + carry_in = result_digit + 10 × carry_out
```

A hidden variable holds the valid tuples for that column. Binary projection constraints connect it to the letters and carries. This lets the same AC-3 engine propagate arithmetic constraints. Repeated letters within a column must agree; absent digits and boundary carries equal zero. This is a binary hidden-variable encoding, with pairwise all-different constraints rather than a specialized global all-different propagator.

The public `csp::Model` API also supports other finite binary CSPs. For example:

```cpp
#include "src/csp.hpp"

csp::Model model;
int a = model.variable("A", {0, 1, 2});
int b = model.variable("B", {0, 1, 2});
model.constrain(a, b, [](int x, int y) { return x != y; });
csp::Options options;
options.solution_limit = 0;
auto result = csp::Solver(model, options).solve();
// Six assignments: the endpoints of an edge have different colors.
```

Keep the model alive while its solver is in use. Repeated calls to `solve()` reset the search state. The two included puzzle encodings have a unique auxiliary assignment for each visible solution; custom models with nonunique hidden assignments may need projected-solution deduplication.

## Data structures and complexity

Let `n` be the number of variables **including auxiliaries**, `e` the number of directed arcs, `d` the largest domain, `v` the visible variable count, `T` the trace cap, and `S` the number of saved solutions.

| Structure | Role and tradeoff |
| --- | --- |
| `vector<int>` domains | Compact, ordered iteration with predictable locality. Membership/revision is linear; the implementation does not claim constant-time domain deletion. |
| Adjacency lists | Revisit only arcs affected by a changed domain; graph storage is `O(n + e)`. |
| `priority_queue` | Process pending arcs with smaller support domains first. Push/pop cost `O(log e)`. Priorities are snapshots at insertion, so an already-queued priority can become stale without affecting correctness. |
| `unordered_set<int>` | Suppress duplicate pending arcs; at most `e` arcs are queued. Expected `O(1)` membership, worst-case `O(e)` with pathological collisions. The set is never iterated, preserving deterministic order. |
| Domain trail | Avoid copying the entire CSP at every decision. Stores previous versions only for changed domains; worst-case `O(n d²)` active-branch domain storage. |
| MRV/degree scan | Select a variable in `O(n + e)` per search node, avoiding mutable-heap bookkeeping for these small models. |

The usual naive AC-3 relation-check bound is **`O(e d³)` per propagation run**. This priority queue adds `O(e d log e)` scheduling work with expected constant-time hash operations; pathological hash collisions can add `O(e² d)`. Backtracking remains exponential, with up to `O(dⁿ)` search states for `d ≥ 2`. Propagation often reduces the explored tree; it does not eliminate worst-case exponential search.

Working storage is `O(n d² + n + e)`, excluding stored model-specific relation data. Cryptarithmetic stores at most 200 candidate arithmetic tuples per column before filtering. Saved solutions add `O(Sv)`, and visible-domain snapshots add `O(Tvd)`. Use `--trace-limit 0` for benchmarks and a finite solution limit when memory matters.

### Measured comparison

For complete 8-Queens enumeration, both modes produce the same 92 solutions:

| Mode | Search nodes | Decisions | Constraint checks |
| --- | ---: | ---: | ---: |
| AC-3 + backtracking | 245 | 408 | 41,936 |
| Backtracking alone | 2,057 | 15,720 | 189,754 |

Reproduce these counters with `python3 python/benchmark.py`; the saved sample is in `examples/benchmark.json`. AC-3 reduces this search tree by about 88%, but its queue and bookkeeping overhead can make it slower on a small instance. Timing depends on hardware and compiler settings; the project makes no universal speedup or optimality claim.

## Limits and output contract

| Option | Default | Meaning |
| --- | --- | --- |
| `--limit` | `1` | Stop after this many solutions; `0` enumerates all. |
| `--timeout-ms` | `2000` | Cooperative solver deadline; `0` disables it. |
| `--max-nodes` | `0` | Deterministic search-node budget; `0` disables it. |
| `--trace-limit` | `2000` | Maximum saved replay events; `0` disables tracing. Maximum accepted cap: 20,000. |
| `--no-ac3` | off | Use MRV backtracking with singleton consistency checks. |

Supported inputs: N-Queens sizes 1–32; decimal cryptarithmetic with exactly two addends, at most 10 distinct ASCII letters, and words of 1–12 letters. Input is case-insensitive. A one-letter word may be zero. Fixed-cell contradictions are valid unsatisfiable puzzle states.

`status` is `solved`, `unsatisfiable`, `solution_limit`, `node_limit`, or `timeout`. **Only `complete: true` means the entire search was exhausted.** Finding one solution does not establish uniqueness. A limit may stop just before exhaustion; completeness is conservatively reported as false. `trace_truncated` reports whether the replay cap discarded events; complete saved solutions can still be selected in the viewer.

Deadlines use `steady_clock` and are checked throughout search and propagation, including periodically during relation checks. They cover solving, including trace capture, but exclude model creation, initial domain copies, JSON serialization, Python rendering, and browser playback. This is cooperative cancellation, not a hard real-time guarantee. Wall-clock timeouts are not deterministic across machines; use a node budget for reproducible runs.

`nodes` counts entered search states, `decisions` counts attempted assignments, and `backtracks` counts branches restored before continuing search. `pruned_values` includes values removed by both decisions and propagation, and includes removals repeated in different branches. Displayed statistics are totals for the full run, not the current replay step. Hidden-domain snapshots are omitted to keep replay files small; auxiliary graph labels show their initial sizes.

The process exits with code **0** for a successfully executed solve, including an unsatisfiable or interrupted search. Read the JSON status to distinguish those outcomes. Invalid arguments return **2** with an error on stderr.

## Reproducible verification

The default Python harness performs **151 exact solution-set comparisons**: known N-Queens counts through N=8, 60 random restricted boards, 60 random or constructed small alphametics, repeated-letter and leading-zero cases, classic SEND+MORE=MONEY, contradictory fixed cells, and checks with AC-3 disabled.

The independent N-Queens baseline enumerates row permutations and tests diagonals. The small-alphametic baseline enumerates digit permutations and evaluates whole-word arithmetic. It does not share the C++ column encoding or propagation code. SEND+MORE=MONEY uses its known unique assignment as a regression, rather than the small-puzzle brute-force baseline.

Additional checks cover deterministic traces/counters, node/solution/time budgets, trace truncation, invalid CLI inputs, HTML data round trips, script-safe JSON embedding, asymmetric binary constraints, parallel relations, isolated variables, and empty domains. The test report records every generated command, a solution-set hash, deterministic counters, and a suite fingerprint. A failure report preserves the seed and command for reproduction. Runtime is deliberately excluded from the fingerprint.

`examples/test-report.json` contains the verified seed-2026 run. Both CTest targets passed with Apple Clang 21 and Python 3.14 on macOS. Other platforms are supported by the build files but were not exercised in this run.

**Algorithmic Constraint Solver & Visualizer | C++17, Python, STL, Graph Theory**

- Implemented a reusable backtracking solver with AC-3 propagation and MRV/degree ordering for N-Queens and cryptarithmetic.
